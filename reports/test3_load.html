Resume bullet

Sustained 205 RPS on the cache-hit path with p95 < 170 ms gateway overhead at 16 concurrent connections; graceful 429 responses with Retry-After: 1 honored past 10 req/s sustained per default tenant, backed by a Redis Lua-scripted token-bucket limiter.

Methodology

Warm the exact-match Redis cache with a fixed prompt ("What is the capital of France?", claude-haiku-4-5, max_tokens=50, temperature=0), then issue 200 requests at each concurrency level through POST /v1/chat/completions. Every request hits the cache, so we measure gateway overhead only — Redis lookup, tenant rate-limit check, response assembly — not provider latency.

What this does not measure: cold-path provider latency (Anthropic / OpenAI round-trip), router decision cost (cache short-circuits before the router), or judge quality. The default tenant's 600 RPM bucket is the binding constraint at high concurrency — the 429s are the rate limiter behaving correctly, not the gateway failing.

Rate-limit behavior (Phase 2.4)

The default tenant ships with a 600 RPM token-bucket implemented as a Redis Lua script (atomic check + decrement). Past sustained ~10 req/s the bucket drains and the gateway responds with HTTP 429 plus a Retry-After header — the correct, protocol-conformant signal a load balancer or client SDK will honor.

Observed Retry-After samples

concurrency=32 → 20 / 200 responses were HTTP 429
concurrency=64 → 182 / 200 responses were HTTP 429

Retry-After header on rate-limited responses: "1"  (seconds)

The c=64 burst depletes the bucket within the first ~200 ms, so 91% of subsequent calls in that level are short-circuited at the limiter — they never touch the cache or providers. This is the cheapest possible failure mode at scale (no downstream load) and the point of the test.

Caveats & honesty notes

  • Cache-hit path only. Cold-path provider latency (typically 700–3000 ms for Haiku/Opus) is not in these numbers.
  • Local loopback. Client and gateway are on the same host; production network adds round-trip you don't see here.
  • Single tenant, single prompt. Cache key cardinality is 1, which is the best-case for Redis hit rate. Real traffic has long-tail keys.
  • 200 samples per level. Enough for p95 to be reasonably stable, marginal for p99 — treat p99 as indicative.
  • RPS at c=64 (256) is inflated by the cheap 429 path; the meaningful sustained-throughput number is 205 RPS at c=16 with zero rejections.
